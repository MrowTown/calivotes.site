# Fix set that will actually stop this (concrete code changes)

## A) Add retry logic to `getAdminSession()` too

Right now, your votes query retries, but your auth query doesn’t — and auth runs first.

In `server/storage.ts`, replace `getAdminSession()` with this:

```ts
  async getAdminSession(token: string): Promise<AdminSession | undefined> {
    const maxRetries = 3;
    let lastError: any;

    for (let attempt = 1; attempt <= maxRetries; attempt++) {
      try {
        console.log(`DatabaseStorage.getAdminSession: Attempt ${attempt}/${maxRetries}...`);
        const [session] = await db
          .select()
          .from(adminSessions)
          .where(and(
            eq(adminSessions.token, token),
            gt(adminSessions.expiresAt, new Date())
          ));
        return session;
      } catch (error: any) {
        lastError = error;

        const code = error?.code || error?.cause?.code;
        const msg = String(error?.message || "");

        console.error(`getAdminSession error (attempt ${attempt}):`, { code, msg });

        const transient =
          code === "57P01" ||
          code === "ECONNRESET" ||
          code === "ETIMEDOUT" ||
          code === "EPIPE" ||
          msg.toLowerCase().includes("socket hang up") ||
          msg.toLowerCase().includes("connection terminated") ||
          msg.toLowerCase().includes("timeout");

        if (transient && attempt < maxRetries) {
          await new Promise(r => setTimeout(r, 300 * attempt)); // small backoff
          continue;
        }

        throw error;
      }
    }

    throw lastError;
  }
```

# Why this still happens even after your pool error handler fix

Your pool `.on("error")` handler prevents the **process crash** from unhandled pool errors (good).

But it does **not** prevent **queries** from failing transiently. Those query failures still bubble up and become 500 responses unless you retry.

Right now:

* votes query: *some* retries ✅
* admin session lookup: **no retries** ❌ (and it’s the first thing every admin request depends on)

So you’ll still “randomly lose admin” even though the server no longer dies.
